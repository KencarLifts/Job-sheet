# Kencar Job Sheets – настройка (GitHub Pages + Supabase)

## 1. Supabase
1. Създайте проект на https://supabase.com.
2. **SQL Editor → New query** → поставете съдържанието на `schema.sql` → **Run**.
3. **Project Settings → API**: копирайте *Project URL* и *anon public key*.
   (Никога не слагайте `service_role` ключа в сайта.)
4. По желание, за по-лесен старт: **Authentication → Providers → Email** → изключете „Confirm email“.

## 2. Конфигурация
В `index.html`, в началото на скрипта, заменете:
```js
const CFG={url:'YOUR_SUPABASE_URL',key:'YOUR_SUPABASE_ANON_KEY'};
```

## 3. GitHub Pages
1. Създайте хранилище в GitHub и качете `index.html`.
2. **Settings → Pages → Deploy from a branch → main / (root)** → Save.
3. Адресът е `https://<потребител>.github.io/<хранилище>/`.
4. В Supabase: **Authentication → URL Configuration** → задайте *Site URL* да е този адрес.

### Забравена парола
Бутонът „Forgot password?“ изпраща линк по имейл, който води обратно към сайта и отваря екран за нова парола. За да работи, в Supabase → **Authentication → URL Configuration** адресът от GitHub Pages трябва да е и в *Redirect URLs*. Вграденият имейл сървър на Supabase праща само няколко писма на час, затова за реална работа добавете собствен SMTP (Authentication → Emails → SMTP Settings).

## 4. Потребители
- Първият регистриран потребител става **администратор** и е одобрен автоматично.
- Всички следващи се регистрират сами, но виждат само екран „Waiting for approval“, докато администраторът не ги одобри в **Settings → Users**.
- Администраторът променя фирмените настройки, номерацията, ролите и може да трие документи. Техниците създават и търсят документи, виждат и принтират всички, но редактират само собствените си. Името на техника се попълва автоматично от акаунта; само администраторът може да го сменя.
- Номерата се дават атомарно от базата, затова двама техници не могат да получат един и същ номер.

## Обновяване на съществуваща база
Ако вече сте пуснали по-стария `schema.sql`, изпълнете само `update_policies.sql` (ограничава редакцията до автора и администратора).

## Импортирани документи
При импорт всеки документ се записва на техника, чието име (или имейл) съвпада с полето Technician; останалите стават собственост на администратора. За вече импортирани документи изпълнете веднъж `fix_authors.sql`. После, ако е нужно, коригирайте имената в Settings → Users и натиснете „Assign imported documents to technicians by name“.

## Архивиране
Само администраторът вижда менюто Settings и бутоните Export/Import.

**Export all** в списъка с документи изтегля всичко в JSON. Supabase също прави автоматични резервни копии (според плана).
